# v1.2 使用反馈逐项对照（历史记录）

本页保留输入包的 v1.2 历史说明；其中“本轮”指当时迭代，2026-10-22 发布核验以 [validation.md](../docs/validation.md) 为准。

当时依据使用者提供的复盘、22页样稿的逐页渲染及v1.1实际文档和脚本进行迭代。复盘中的耗时分摊、工具返回和历次操作属于使用者报告，未据此宣称独立重放全部历史过程。以下是问题与处理的对照，不是新一轮完整PPT制作试跑结果。

## A—J不足对照

| 项 | 对照v1.1的判断 | v1.2处理 |
|---|---|---|
| A 工具链只有能力、缺实施路径 | 部分成立。v1.1已增加环境预检和来源恢复，但制作、渲染、媒体的可操作路径仍不足 | 增加toolchain.md和media-workflow.md，按现有能力选择路线，列验证与失败分支，不自动安装或假定某个库存在 |
| B 时长区间狭窄、规划太晚 | 成立。此前有预算要求，但没有前置数值求解工具 | 增加plan_timing.py和timing.md；在大纲/讲稿成稿前算可行字数区间，发现无解或余量很小时先处理预算，不反复重建PPT |
| C 学习强国硬要求无恢复路径 | 对初版成立，对v1.1不完全成立。v1.1已有公开浏览器成功实例、人工全文及经确认的等价原始来源路径 | 保留已确认的学习强国第一优先，不接受“自动换源即合规”的建议；补可执行工具链并复用source-recovery.md，不把一次读取失败升级成全站不可访问 |
| D 视频要求多、获取和嵌入方法少 | 部分成立。v1.1有授权与失败处理，但编码、体积、裁剪及播放验收方法仍需补齐 | 增加媒体获取、归属核验、片段/体积预算、转码建议、显式播放模式和分层实测方法；不把一个生成库的行为当全部PowerPoint默认 |
| E 保留口径与去防御性缺裁决 | 成立，原原则不足以稳定执行 | 用“删除后是否改变对象、范围或结论理解”判断必要性；必要信息就近放数字标签/图注，长解释另行组织。删无信息量辩解，不把所有脚注一刀切禁止 |
| F 审查循环缺收敛控制 | 部分成立。已有修复与回归要求，范围与升级动作不够具体 | 明确局部视觉、事实传播和全局改动三类复审范围；复用仍有效的证据。同一问题反复失败先诊断根因，不自动判环境问题或降级严重度 |
| G 冻结要求无可执行机制 | 成立，原规范没有配套快照工具 | 增加freeze_review.py：显式文件清单、新目录副本、SHA-256清单及只读复验。冻结后在新工作版本修改，不覆盖在审快照 |
| H 审计数字容易被误读 | 成立。汉字计数与含切换的total_minutes不足以直接指导规划 | 保留旧字段，增加清楚区分的口播/主体/现场区间、可行字数与当前差额、输入文件指纹；估算仍不等于排练 |
| I 播放验收缺方法与隐私边界 | 成立。未验证状态正确，但执行和用户交接指引不足 | 提供快速冒烟与完整播放两级清单，分别记录。优先只捕获PPT窗口；一分钟检查不能冒充十二分钟完整播放，无法观察声音不能宣称有声 |
| J 多文档手写数字不同步 | 成立，原来缺测量权威来源和送审一致性检查 | 候选文件绑定的审计JSON成为页数/字数/估算的计算依据，其余文档引用；冻结工具核对候选与测量指纹，不自动填作者判断或审查结论 |

## 12项运行阻塞的覆盖关系

1. 搜索返回不可信内容：source-recovery.md与toolchain.md要求实际打开候选并核验；工具输出可疑不等于可无证据断言整项服务造假。
2. 学习强国静态入口无正文：v1.1已增加详情页、真实浏览器渲染、人工全文及经确认替代路径，本轮保留并接入工具链。
3. 现场重复构建浏览器抓取链：使用宿主已有浏览能力、保留正常会话、按加载状态和真实链接操作，避免猜接口和重复初始化。
4. 视频来源与下载：media-workflow.md给出候选获取、归属、片段、编码和验证路径；不借反馈里的单一视频地址建立固定依赖。
5. python-pptx未安装：v1.1已纠正“缺一个库等于缺能力”；本轮补具体工具路线，不强制安装一个工具。
6. 批量图片映射错位：review-control.md要求稳定资产ID、哈希、来源说明和目标页对应；按带标签的预览核对，不按返回顺序猜。
7. 讲稿完成后才发现过短：前置规划字数预算，成稿后再以实际备注校验。
8. 可行区间过窄：计算区间宽度并报告余量；不得无依据收窄语速或加长无关视频“做绿”结果。
9. 修复又引入回退：影响范围驱动复审，保存开放问题和回归证据。
10. 审查中改文件：送审快照与编辑副本分离，审查前后验证清单，不让审查追逐移动版本。
11. 统计口径变成免责段：必要限定就近表达，删除模板化辩解；不藏掉影响读者理解的条件。
12. 放映结果无法确认：提供分层检查、明确待补验证与最小用户动作，不以像素变化替代声音/完整播放证据，不把待用户验证说成全面通过。

## 样稿中可直接观察的内容与分区问题

- 第4页：信息类型混在连续段落中。改进应从本页问题和信息关系出发，而非仅增加字数。
- 第6/7页：相同高度容器没有适应不同文本长度，替代字体渲染出现压底风险。需以目标渲染检查，不能把替代字体结果直接称作目标PowerPoint缺陷。
- 第13页：领域案例和日期开头的材料使用同级容器，分区没有准确表达语义关系。
- 第16页：图文已有结构，但合图中的多个对象与说明需要稳定对应。
- 第18页：不同单位、对象与时间的数据用了相同大数样式，标签与口径应先形成完整信息单元，再决定是否适合视觉比较。

新增page-planning.md，并将正文的“内容足以支撑本页任务”和“空间/分组清楚”分别设为验收项。封面、目录、章节、引用、问题和视频页按各自用途判断，不按固定字数、填满率或最少卡片数处罚。保留认可的页眉/标题字号和模板外框，不用重设计掩盖内容规划缺口。

## 明确不照搬的建议

- 不把学习强国优先擅自改成可无确认跳过的主源要求。
- 不为通过计时而虚构更窄的语速区间、删掉必要互动或加入无关长视频。
- 不把相同问题两轮未解决自动分类为环境原因，也不通过降低标准关闭问题。
- 不宣称所有视频默认单击或默认自动播放，必须核对实际产物。
- 不宣称一分钟快速检查完成了全片播放和声音验证。
- 不承诺这些修改必然节省一半时间。效率和完整流程效果需要后续真实使用证据。

## 本轮验证边界

本轮针对规范、辅助工具、冻结一致性和安全性作修改与验证；没有改动使用者的PPT原件，没有重新创作整场材料，没有在使用者电脑安装或实测PowerPoint。目标平台的实际加载、字体、媒体与完整排练仍须分别记录证据。

## 已完成的有限验证

整合后合成测试共79项，在本轮Linux/CPython 3.12.14运行通过；文件引用、JSON、Python语法和预检通过，技能目录无新增字节码缓存。新增工具的独立测试包括区间计算、不可行预算、候选变更、冻结/复验、路径与覆盖保护、Unicode及编码回归。

另外只读检查了使用者的22页样稿，实际提取备注汉字代理数7026。按反馈提供的720秒视频、120秒预留计算，主体约40.104—42.5478分钟，现场约42.104—44.5478分钟，与反馈算例一致。这里复核的是候选抽取与计算；没有据此独立确认媒体实际播放720秒、目标应用有声或现场排练达标。样稿与原始反馈不包含在技能分发包中。
