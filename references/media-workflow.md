# 媒体获取、嵌入与放映验收

用于S03、S05、S06和S09。默认仍是相关真实视频并嵌入PPTX；数量、片段长度和播放方式按内容与任务决定。默认嵌入不等于默认自动播放，也不等于必须点击视频本体。正文主源要求仍按[source-recovery.md](source-recovery.md)执行。

## 1. 获取路径：先确认可用素材，再写满讲稿

1. 在本轮具体制作范围内，搜索并打开官方视频落地页，核对主题、发布时间、完整内容、下载／使用条件。先尝试可见的官方“下载”、官方提供的媒体文件，或用户提供且可合法使用的本地文件。公开可播放不自动代表允许下载、剪辑或再分发；权利和用途存疑时暂停该素材并换合适候选，必要时询问。
2. 页面只有脚本壳时先用已有获准渲染浏览器打开真实详情页，按可见播放器启动。不要从首页脚本猜私有接口，不从第三方下载站代取。
3. 官方没有下载按钮时，只有宿主工具明确允许网络观察／下载，且内容、权利与本轮范围允许，才可观察实际已渲染公开播放器产生的媒体请求。Playwright公开文档提供`page.on('response', ...)`等网络事件，但这不说明当前宿主暴露此接口。浏览器只允许UI／DOM操作时，不自行接CDP、取内部状态或另起抓取器绕过工具边界。
4. 对实际观察到、无受保护凭据且允许下载的公开媒体资源，核对域名、响应类型与页面内容，再使用已获准下载能力。HLS／DASH等分段资源只在已有工具明确支持且合法可用时处理；仅看到`blob:`不是取得可下载原片。不要拆DRM、重放访问令牌／Cookie、猜签名参数、绕过登录／付费／访问拒绝。不要保存含凭据的请求头或整站网络日志。
5. 一个候选失败后，记录实际原因，再看另一个独立允许访问且内容合适的官方候选；不是绕过原资源限制。现有可用路径耗尽时，请用户提供合法文件，或明确申请改成在线链接并说明离线／网络影响。不能静默取消视频或用占位框过关。

依据：[Playwright网络事件](https://playwright.dev/docs/network#network-events)仅证明该库有公开能力，不构成本轮访问或下载授权。仅修改技能包时不执行上述素材获取。

## 2. 来源、内容与归属要分别登记

每项使用固定`media_id`，至少记录：落地页URL、原发布者、承载平台、实际获取方式与日期、使用依据／限制、源文件及SHA-256、原片实测时长、源片起止时间、输出片段及SHA-256、输出实测时长、编码／尺寸／文件字节数、使用页、嵌入或链接、播放模式、验证层级与证据。来源URL与文件哈希各有用途，不能相互替代。

- 实际看片头、片尾、台标、水印、字幕与关键画面，区分“网页转载平台”“原发布者”“出品／制作方”。网页页脚、备案、网站版权声明不是该视频的制作署名。证据不足只填未知，不凭台标猜完整出品关系。
- 记录归属证据位置，例如“原片00:03台标”“片尾20:40制作署名”。保留应保留的水印、字幕与归属，不裁掉它们只为画面干净。
- 图像也按ID绑定文件、来源与内容。批量工具返回后按实际文件／对象ID核对，必要时做带ID、文件名和简短对象名标签的缩略图总览；不能凭返回顺序把地点、人物或事件配错。
- 裁剪服务于完整论据与时间预算：保留必要前后文，不把否定／条件剪掉，不拼接制造不存在的因果。记录裁剪理由和片段原文位置。视频变长会挤占口播，不自动补齐全集，更不固定21分钟或12分钟。

## 3. 时长、体积与编码

先用已有媒体工具测原片和输出片段，再把实际播放秒数交给时长规划。容器有视频／音频流不代表内容可看、声音可听；ffprobe报告不是播放证据。

以下均是未执行的示例；先确认ffprobe／FFmpeg存在、宿主允许且本轮授权处理该文件。无需为看此文安装工具。

```sh
ffprobe -v error -show_entries format=duration,size,bit_rate:stream=index,codec_type,codec_name,width,height,pix_fmt,sample_rate,channels,duration -of json "source.mp4"
```

体积按预算计算，不设任意统一MB阈值：媒体字节数约为`时长秒 × (视频平均bit/s + 音频平均bit/s) ÷ 8`，另留容器与封装余量。总PPT预算还要加图片、其他嵌入媒体与交付渠道限制；实测文件大小决定能否交付。例如720秒、视频800 kbit/s、音频128 kbit/s约83.52 MB（十进制，未计开销），只是算例，不保证可读性或推荐固定码率。先保留字幕可读、运动画面清晰与可听语音，再按实际带宽／容量决定分辨率与质量。

兼容性起点采用MP4容器、H.264视频与AAC音频，这是[Microsoft推荐组合](https://support.microsoft.com/en-us/powerpoint/video-and-audio-file-formats-supported-in-powerpoint)，不是所有应用／机器播放必过的保证。已有FFmpeg且含相应编码器时，可按实际片段重新编码；以下仅演示从02:00截取3分钟，不是默认片长或最终编码标准：

```sh
ffmpeg -hide_banner -n -ss 00:02:00 -i "source.mp4" -t 00:03:00 -map 0:v:0 -map 0:a:0 -c:v libx264 -pix_fmt yuv420p -crf 23 -preset medium -c:a aac -b:a 128k -movflags +faststart "clip-v001.mp4"
```

- `-n`避免覆盖已有文件；示例要求第一视频流和第一音频流存在，缺音轨会失败，不悄悄生成无声稿。多音轨先听辨并选择所需轨道，不盲选第一条。
- 质量值、音频码率与像素格式是候选参数，应看片、听音、测大小后调整。默认不拉伸／升分辨率，不用压缩掩盖原片缺陷。
- `+faststart`把MP4相关元数据移到文件开头，有利于渐进式读取，不自动修复坏编码、剪辑问题或PowerPoint设置。`-c copy`不重新编码，且裁剪边界可能受关键帧影响，不能据命令参数认定精确剪到指定帧。
- 重新探测`clip-v001.mp4`并核对开头／结尾、画面、音轨及实际时长；保存源区间与输出时长，容器时间／帧边界的差异不能直接抹掉。

可选全文件解码检查，不播放、不生成媒体文件：

```sh
ffmpeg -v error -xerror -i "clip-v001.mp4" -map 0:v:0 -map 0:a:0 -f null -
```

检查进程确实结束、退出码和错误输出；成功也只表示所选流的本次解码检查通过，不表示PowerPoint或扬声器已测试。命令依据：[FFmpeg命令与流选择](https://ffmpeg.org/ffmpeg.html)、[编码器](https://ffmpeg.org/ffmpeg-codecs.html)、[MP4封装](https://ffmpeg.org/ffmpeg-formats.html)、[ffprobe字段](https://ffmpeg.org/ffprobe.html)。Windows、macOS、Linux都须使用各自实际安装的可执行程序与编码器，不能从命令存在推断功能一致。

## 4. 嵌入与播放模式

优先宿主正式PPT工具或PowerPoint自身：Windows在“插入 → 视频 → 此设备”选择插入，不选“链接到文件”；macOS使用“插入 → 视频 → 文件中的影片”等当前界面入口，确认未选链接。界面名称随版本变化，按实际UI判断。[Microsoft插入及播放说明](https://support.microsoft.com/en-us/powerpoint/insert-and-play-a-video-file-from-your-computer)

保存后检查媒体关系确实指向PPTX内的媒体内容，而非外部路径或只有封面图。重新打开同一版本，确认封面、字幕、比例、裁剪和播放长度。库生成成功或ZIP里出现MP4只能证明结构层，不能替代放映。

在视频对象的“播放 → 开始”显式选择并记录下列一种，以当前版本可用项为准：
- `In Click Sequence`：按放映的下一步操作启动，可能点击页面或使用前进键。
- `When Clicked On`：点击视频对象启动。
- `Automatically`：按其动画顺序自动启动，前置动画可能影响开始时点。

不能把某个python-pptx文件的表现写成所有PowerPoint的默认。现行Microsoft Windows说明将`In Click Sequence`列为默认，其他工具／版本可能不同。用户未要求自动播放时不擅自承诺自动播放；制作时选择适合讲述的模式，交付说明写清实际操作并验证。开始方式、循环、结束后行为和音量都看实际设置；没有用户要求不把系统音量统一调到80%。操作说明独立交付，不塞进自然口播备注。

## 5. 目标机验收：分层记录，不把一分钟当全片

开始前核对最终候选哈希、目标操作系统与PowerPoint版本、视频页和媒体ID。优先仅捕获PowerPoint窗口／放映区域，避开其他窗口、通知、凭据和无关桌面；已渲染的幻灯片图更适合静态视觉证据。若工具只能获取整屏，先按宿主权限要求处理，无法限定采集范围就请用户按清单报告，不默认持续截屏。只观察必要的应用音频，不录麦克风／全系统无关音频来凑证据。

### A. 快速冒烟检查，通常约1分钟起

每个勾选项都需真实观察，可由已获准的操作者或用户完成：

- [ ] 在目标应用打开该候选，无修复／缺媒体提示；从当前视频页进入放映后，再核对标题与页码，避免起始页错位。
- [ ] 按已配置模式启动；画面开始推进，实际播放器计时／进度增加，不只看到静态封面或鼠标变化。
- [ ] 在预期输出设备听到该片声音，语音可辨；分别检查PPT媒体静音、应用／系统音量和输出路由。用户指定80%时注明设置的是哪一层，不能以音量数字代替听音。
- [ ] 用可见进度条跳到代表性中段、接近结尾，各播放一小段检查画面与声音；最后能按预期停止／返回并进入下一页。

启动、进度、音频和seek分别记`pass/fail/unverified`。用户操作则标“用户报告”并记录时间、版本和观察范围，不称智能体独立实测。一分钟不足以完成某些文件的检查；按实际用时报告。seek到结尾只验证末段，不能标连续全片通过。

### B. 整段连续播放与现场排练

本轮要求播放到结束时，必须在目标PowerPoint从片段开始不跳播地连续播放完整时长，观察有无中途卡死、异常停止与声音问题，记录实际起止、完成状态及观察范围。12分钟片段至少需要其真实播放时间，不能用1分钟抽检或文件解码替代。未持续观察音频的部分如实标明。现场完整排练还需口播、切换、停顿及互动计时，不能从视频测试推导。

### C. 自动化可用时与停止条件

已获准、真实连通的PowerPoint自动化可用公开的[SlideShowView.GotoSlide](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.slideshowview.gotoslide)跳页，再读[SlideShowView.Slide](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.slideshowview.slide)核对当前页，不把编辑态Select成功当放映态成功。若支持[Player](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.slideshowview.player)，可用其[State](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.player.state)与[CurrentPosition](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.player.currentposition)辅助观察；先绑定实际媒体形状ID，别猜对象索引。播放状态／时间前进仍不能证明音频从目标扬声器传出，也不能替代可见画面。

没有这类接口就用正式UI，不移植Windows COM到macOS／Linux，不启用宏或修改安全设置来凑能力。截图像素变化最多是辅助线索，不能排除鼠标／动画变化或证明有声。若无法观察音频或真正放映状态，保留该项`unverified`，给出准确原因和上面最小补测步骤。只有纠正页码、调整已知播放设置、修复媒体或恢复连接等新证据才重试；没有新假设就停止同一测试，不按固定“两次失败”硬判环境原因。

记录模板：`候选哈希｜应用/版本｜页/媒体ID｜播放模式｜启动｜进度｜声音与输出设备｜seek范围｜连续播放起止/结果｜观察者/时间｜证据｜未验证原因/下一步`。文件结构、解码、替代应用播放、目标PowerPoint冒烟、目标全片和全场排练分别报告。必需项仍未验证时验收未完成，不能写“全部通过，只需用户随便点一下”。
