# 先定时长窗口，再写完整讲稿

用于 S04 前置预算与 S06 候选核对。先计算可行区间，不要等 PPTX 做完才发现备注字数差数千字。脚本只给预算和缺口，不补写、凑字或修改讲稿，也不证明内容充分。

## 保持原要求与计量口径

- 默认主体＝口播＋视频，主体至少 40 分钟；现场＝主体＋全部切换／停顿／互动预留，现场不超过 45 分钟。预留必须在 45 分钟内，不能挪到上限外。主体上限由现场上限及非负预留共同约束。
- 未排练时 230—250 字／分钟是估算范围，不是已测语速。必须在整个范围两端都满足约束；不能为了让结果通过，随意改成 240—250。只有可信排练等依据支持时才更新语速假设，记录依据。
- “字数”与语速须使用同一口径。PPTX 审计只数 Han 汉字码位：数字、英文、标点不计，非口播引用和舞台指令仍可能被计入。这个数是代理量，不等于总口播字符数，也不是排练秒数。
- 视频用本次实际计划播放片段的总时长，不自动使用整段源片长度；得到媒体测量后再更新。工具不读取、测量或播放媒体。视频与口播按不重叠计算，预留中的停顿不要与实测语速已含的停顿重复计入。

## 计算与前置命令

设语速慢端 r_min、快端 r_max（字／分钟），视频 V、预留 R、主体下限 B、现场上限 S（分钟），则：

```text
下限 L = max(0, ceil(r_max × (B − V)))
上限 U = floor(r_min × (S − V − R))
可行当且仅当 L ≤ U
窗口宽度 = U − L（可行时）；整数候选数 = U − L + 1
```

视频自身已满足主体下限时，口播下限为零，不输出负目标字数。视频加预留超过现场上限、最低主体加预留超过现场上限，或两端语速要求冲突时，报告不可行。不可行的 min/max 保留冲突边界，width_characters 为 0、gap_characters 为 L−U，不伪造可行目标或中点。

在技能根目录运行，`python` 替换为宿主已确认的 Python 命令：

```sh
python -B -X utf8 scripts/plan_timing.py --video-seconds 720 --reserve-seconds 120 > timing-plan.json
python -B -X utf8 scripts/plan_timing.py --video-seconds 720 --reserve-seconds 120 --current-characters 2273 > timing-draft.json
```

规划器不需要 PPTX、媒体文件、第三方库或安装。视频与预留显式必填，其他默认值是 230、250、40、45；可用 `--rate-min`、`--rate-max`、`--body-min-minutes`、`--session-max-minutes` 表达有依据或经用户明确更改的条件。`--current-characters` 不填时当前字数、缺口和当前分项时长为 unknown/null，不凭空记零。已知零字应显式传 0。

12 分钟视频＋2 分钟预留得到 [7000, 7130]，宽 130 字（含 131 个整数）。初稿若为 2273 个同口径字符，离下限差 4727；7026 个字符的估算为：口播 28.1040—30.5478 分钟，主体 40.1040—42.5478，现场 42.1040—44.5478。慢端距现场上限约 27.13 秒，不能用“落入窗口”代替排练。

## 分阶段使用，避免为每次改字重建 PPTX

1. 先用暂定视频／预留计算条件式预算，确定是否有可行窗口；未知媒体时长须标“暂定”，不阻塞不依赖它的大纲工作。
2. 把可行口播总量按真实论证重点分配到模块／页，不机械平均分配。在独立讲稿／大纲中修改、计数、重算，先消除大幅缺口。
3. 取得实际媒体片段与可靠时长后重算；讲稿初步稳定再写入候选 PPTX。字词调整可先改讲稿再批量更新候选，不能省略最终文件同步。
4. 候选完成后以审计 JSON 里的抽取计数和分项估算为准；核对隐藏页、实际播放顺序、非汉字口播、未计入或不读出的备注，再排练。用新证据修正计划，不把估算标记为通过。

## 审计字段与证据边界

```sh
python -B -X utf8 scripts/audit_pptx.py candidate.pptx --video-seconds 720 --transition-seconds 120 > candidate-audit.json
```

审计为兼容旧调用保留 `--transition-seconds` 名称及默认 45 秒；它在模型中等于全场预留，不是每页预留。必须按本轮真实计划显式传参，不要把该默认值当测量。`--video-seconds` 的旧默认 0 也不证明无视频。与规划器统一使用同一组数值和 40／45 分钟约束。

- 旧 `timing_estimate.narration_seconds`、`total_seconds`、`total_minutes` 保持原含义、精度和字段；其中 total 始终是含视频和预留的“现场”，不是“主体”。
- 新增 `timing_estimate.speech_*`、`body_*`、`session_*`，每类有 minutes/seconds 的 min/max。新字段显示四位小数；约束判断使用未舍入值。
- `timing_budget.target_character_interval` 给出 min/max、feasible、width_characters、integer_target_count、gap_characters。`planned_breakdowns` 为下限／中点／上限的分项估算，不可行时为 null。
- `timing_budget.current_characters` 以候选抽取的 Han 代理数报告 below_target／within_target／above_target／no_feasible_interval、缺口、超额及剩余字数空间。within_target 不是实际时长验收。
- `timing_budget.count_basis` 明示统计所有列出页（含隐藏页），另列隐藏页及其字数、缺失页／不可读备注。不会擅自排除隐藏页，也不假定它们一定播放。实际播放顺序与总口播字符数未知；缺备注时抽取值仍可为 0，但不把实际讲话时长说成 0。
- `measurement_status` 把实际口播／主体／现场秒数标为 null，媒体只记输入未验证，语速只记假设。外部 ffprobe 测量与目标 PowerPoint 播放证据分别保存，不由本脚本代证。
- `input_fingerprint` 是同一打开候选的 SHA-256 与字节数：`{"sha256":"…","size_bytes":123}`。审计前后复核字节，检查路径未被替换；候选变化即报错，不给旧测量绑定新文件。送审冻结时再次核对，不能把路径相同当版本相同。

成功计算退出 0，包括已明确报告不可行的预算；非法参数、非有限数、负数、逆序／零语速、文件／ZIP 等错误退出 2，stdout 为 UTF-8 JSON。`--help` 仍是普通帮助文本。沿用 [runtime.md](runtime.md) 的父进程显式 UTF-8 解码与 `-B` 无新缓存约定。

测试只证明纯计算、合成候选审计和本次运行平台的编码／缓存回归；不表示 Windows 桌面演示、PowerPoint 播放或完整制作任务通过，不据此声称节省固定比例的工时。
