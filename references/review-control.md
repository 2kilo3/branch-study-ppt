# 候选快照、测量权威与有限复审

本文件落实[workflow.md](workflow.md)的S06—S09和[review.md](review.md)的独立审查，不改变学习强国主源要求、已确认标准或[security.md](security.md)的权限边界。只在获准制作／审查任务中执行；安装、升级或打包技能不触发真实PPT试跑。

## 1. 先固定输入，再开始审查

“冻结”是工作流约束和可复核的字节快照，不是改操作系统权限：

1. 作者停止写入本轮工作文件，固定需求版本、候选版本和本轮必需材料。先对最终候选运行审计，不能用上一版本审计冒充当前测量。
2. 明确允许复制的文件角色：candidate（候选PPTX）、ledger（来源主张台账）、outline（大纲）、media（媒体清单）、run_state（状态）、audit_metrics（机器审计JSON）。candidate和audit_metrics必需，其余按当次任务要求显式列出；完整制作任务仍应包含其原本要求的台账、大纲、清单和状态。不要为了凑角色创建空文件。
3. 用freeze_review.py复制到一个全新的兄弟目录，生成仅含相对路径、字节数和SHA-256的manifest.json。复制仅针对显式文件，不递归搜集工作目录，不带入旁边的私人文件。没有“复制整个桌面／项目”的默认行为。
4. 在快照之外保存工具返回的manifest_sha256，并随审查交接给审查者。这个外部摘要用于检测manifest本身被改写，不能从待审目录临时重算后当成可信基准。
5. 审查者先verify，再只读审查快照；审查报告、重渲染结果和问题表写到另一个目录。审查结束及交付前再verify。任何changed、missing、unexpected或unsafe均需处理，不能把“工具运行结束”当成完整性一致。
6. 审查期间不得写入快照。作者如需继续修改，另建工作版本；旧审查只对旧快照有效。修复后重算审计、创建新快照并交接差异，不覆盖旧快照、不让审查者追逐持续变化的文件。

示例：以下目录和文件名均是通用占位名称。输出目录的父目录须已存在；work、snapshots、reports是彼此分离的目录。

```sh
python -B -X utf8 scripts/freeze_review.py freeze \
  --private-stable-workspace \
  --input-root work \
  --output snapshots/review-001 \
  --candidate candidate.pptx \
  --ledger source-claim-ledger.md \
  --outline outline-and-timing.md \
  --media media-manifest.md \
  --run-state run-state.json \
  --audit audit.json \
  --require-role ledger --require-role outline \
  --require-role media --require-role run_state \
  > reports/review-001-freeze.json
```

将上一步返回的manifest_sha256原样代入下例，不是字面使用占位符：

```sh
python -B -X utf8 scripts/freeze_review.py verify \
  --snapshot snapshots/review-001 \
  --expected-manifest-sha256 <上一步保存在快照外的64位摘要> \
  > reports/review-001-integrity.json
```

命令返回：freeze成功为0；verify字节一致为0，差异为1；参数、输入、安全路径或读取错误为2。JSON使用UTF-8；父进程须按UTF-8解码。integrity=consistent仅表示指定快照与可信摘要相符，review_status仍是not_assessed，绝不自动给PPT、来源、播放或验收判PASS。

### 路径和失败边界

- 根目录和输出位置可由当次任务在运行时指定；清单内只写相对路径。输入拒绝绝对路径、盘符、反斜线、父目录穿越、同名／大小写冲突、保留清单名，以及同时作为文件和目录的冲突路径。
- 不覆盖任何已有输出目录，不接受输入根目录与快照嵌套。不跟随符号链接、Windows重解析点／junction，拒绝多硬链接输入和异常文件类型；verify同样报告异常快照成员。
- 不调用chmod、ACL、安全设置或系统锁定。新文件使用系统通常的创建权限。freeze必须显式提供--private-stable-workspace（API对应private_stable_workspace=True），确认输入、输出及其祖先目录位于私人、稳定且没有其他写入者的任务工作区；这只是调用者确认的前提，不是工具自动证明安全。不能确认时，不运行freeze。
- 此可移植实现不是读写隔离沙箱，也不提供系统级不可变性。路径检查与文件打开之间仍存在祖先目录替换竞态：恶意并发替换父目录为符号链接／junction，可能在后置检查前把读取或写入导向目录外；最终文件的O_NOFOLLOW不能保护全部祖先。不要用于攻击者可同时修改目录的场景。开始前停写、复制中检查变化、结束后复核和审查前后verify只控制普通版本漂移，不宣称抵御恶意竞态。verify虽不写文件，其路径读取也要求同样可信、稳定的目录树。
- 必须先根据实际工作区隔离和现有访问条件确认上述前提，不能为通过命令检查自动添加该参数、把共享目录默认视为私人，或把参数当作新增权限。不得自行调整ACL／chmod来制造满足条件的外观。
- 复制中失败可能留下不完整新目录；工具不自动递归删除、不自动覆盖重试。没有有效manifest和独立保存的摘要就不能作为送审版本。保留失败现场，修复原因后选择新的输出名；删除残留须另按权限处理。
- 工具不验证PPT能否打开，不解析视频，不检查来源真假，不判断大纲与讲稿语义是否一致。输入文件虽可能含私人路径或其他资料，快照应留在获准的私人任务位置；不能作为技能发行包素材或顺带上传。分发仅包含通用代码、文档和合成测试。
- 六角色清单不是任意附件打包器。额外原文证据、渲染图和媒体文件如需交接，按已有权限单独提供稳定ID、相对位置和内容哈希；不要悄悄扩大复制范围，也不要宣称它们已包含在这份快照内。

## 2. 机械测量只认一个权威，不手写四份副本

audit.json的input_fingerprint.sha256与size_bytes必须对应本轮candidate的精确字节。freeze会拒绝未绑定、绑定旧候选或错误结果的审计。这个绑定只证明审计声明针对哪个文件，不证明审计工具或作者的全部判断正确。

统一引用ID／JSON字段，而不是在台账、大纲、媒体清单、run-state中各写一套数字：

| 信息 | 权威位置与使用方式 |
| --- | --- |
| 候选标识 | manifest中的candidate记录和candidate_sha256 |
| 页数 | audit.json → slide_count；隐藏页、缺失部件等仍要看审计边界 |
| 备注汉字码位数 | audit.json → summary.total_notes_chinese_characters；不是口语词数或已排练时长 |
| 目标字数窗口 | audit.json → timing_budget.target_character_interval |
| 口播／主体／现场估算 | audit.json → timing_estimate.speech_minutes、body_minutes、session_minutes；分别引用，不能用现场时间冒充主体 |
| 视频时长、切换与互动预算 | 审计settings记录所用输入；实际视频时长须有对应媒体ID的测量证据，预留预算是规划输入，不伪称从PPT自动测得 |
| 来源核验、视觉结论、问题关闭、实际播放、排练计时 | 由相应审查／实测记录负责，不能由哈希、计数或估算自动生成通过状态 |

例如大纲写“字数见audit:summary.total_notes_chinese_characters；时长见audit:timing_estimate.body_minutes”，并绑定同一候选摘要。需向用户展示具体数字时，从该审计读取后生成当次显示值，保留引用；候选变化即重算，而不是手动修补过期数值。机器结果可以自动生成展示，但不会自动同步全部事实判断、媒体归属或验收状态。

run-state引用本轮manifest、audit和报告ID，负责流程位置、开放问题、阻塞和下一步；不由作者预填审查者的PASS。来源台账负责主张与原文；媒体清单负责素材身份和使用映射；大纲负责教学顺序与讲解意图。共享机械值不再重复维护，但各自的人类判断仍须复核。

## 3. 初审完整，复审按实际影响扩展

初次独立审查仍须看整套缩略图、逐页清晰页面及备注，覆盖全部事实、来源、媒体和必需验收项。初审未完成的范围不能借“增量复审”跳过。

修订交接至少包含：旧／新候选摘要、需求版本、变更文件和页／对象、变更性质、受影响的主张ID／素材ID、预计复审范围及未解决问题。哈希只能发现文件不同，不能自动判定哪些页面或语义没受影响；作者差异说明也不是审查者的通过保证。

| 改动类型 | 最小复审范围 |
| --- | --- |
| 局部排版、裁切或文字位置 | 重渲染并细看改动页；若改变叙事、衔接、视觉连续性或跨页对应，再看前后邻页。比较新旧页，检查修复是否造成字号、换行、溢出或图文错配回退 |
| 引语、数字、人名、地点、因果或其他事实更正 | 复核相关原文；检索画面、图表、图注、备注、台账和所有重复使用位置，不限改动页。检查更正后的叙事、引用归属和时长影响 |
| 全局字体、母版、模板、统一样式或全局替换 | 对全套受影响页面进行回归；字体／母版通常影响全页，不能以“只改一处代码”为由只看一页 |
| 媒体替换、裁剪、时长／编码／播放设置改变 | 检查所有使用该素材的页面、嵌入关系、图文对应、播放方式和相关实测；重算全套时长。不能沿用旧视频的播放通过记录 |
| 页面增删、重排、全局讲稿／结构改动 | 核对全套放映顺序、页码映射、前后衔接、隐藏页、叙事和总时长；对所有受影响页面重新视觉检查，广泛影响时全页回归 |

每次修复都要验证原问题和可能引入的回退。增量审查省的是已证明不受影响的重复工作，不是降低标准。最终交付需确认所有初审覆盖与后续复审证据覆盖了最终候选，不可仅凭最后几张改动页宣布整套完成。

### 原文证据可复用，但不能假装重新访问

- 初审按来源规则独立打开原文并记录完整内容、详情URL、获取日期、原文定位、内容哈希、独立核验者和适用时间。作者旧截图不是独立核验保证。
- 同一审查链的后续轮次，若主张与措辞未变、证据内容与来源身份未变、适用期未变且没有更正／更新信号，可以引用已完成的独立证据记录。明确标为“复用证据”，不要每轮无差别重开约三十个URL，也不要写成“本轮重新打开”。
- “目前／最新／现任”等时效主张、来源有更正、证据过期或不完整、主张改写、原文支持存在争议时，重新查对应原文及后续更新。新的独立审查者须判断证据可用性，不因作者声称“不变”而直接通过。
- 学习强国主源政策和[source-recovery.md](source-recovery.md)仍适用。缓存不能把未验证主源变成已满足，也不能未经用户批准替换来源要求。

## 4. 收敛靠证据与根因，不靠降低等级

问题使用稳定ID，记录首次发现、严重度、状态、每轮修复、复验证据与新回退。原问题改了页码也不另建一个“从未失败”的新ID。

同一问题连续两次修复／复验仍未关闭，停止重复相同尝试，进入根因检查：复现条件是否清楚、修复是否落到正确版本、工具能力是否足够、内容约束是否冲突、是否缺少来源或目标机证据。报告已尝试什么、观察到什么、尚缺什么及下一项可区分原因的检查。

“两次失败”不等于自动判定环境性阻塞。只有具体工具／权限／目标环境证据支持时才如此记录；已知缺陷仍为fail，证据不足为unverified。不能自动降低P0／P1、换审查者求通过、删除必查项或擅改需求。

- P0／P1保持真实开放，直至独立复验凭新证据关闭；重大回退作为问题继续跟踪。
- P2如确实不影响任何必需项，可标“开放但不阻断”，或根据用户明确决定标“延期／接受取舍”。不假装修好了，也不把P1自动改名为P2。需要用户决定的取舍一次说明影响，避免审美偏好无限循环。
- 用户明确改变标准时，更新需求版本并记录原话／范围；新标准只对后续判断适用，不追溯伪造旧版本通过。
- 达到已确认标准且所有影响验收的开放项消除后停止。若缺少必要实测条件，诚实移交待验证候选，不做无休止的同类像素采样。

## 5. 待用户验证的候选，不等于已全面验收

candidate_ready_for_user_validation与fully_accepted是不同状态。必需目标PowerPoint播放仍为unverified时，可按用户授权提供候选和精确待测步骤，但不能同时写“无阻塞”“全部通过”“已完整验收”。

交付说明应简短说明：已完成哪些范围、唯一或全部仍待验证项、在哪个候选／哪页、如何触发、预期时长与声音、谁来验证、缺失证据如何影响验收。实际播放、音量和结束点必须来自对应设备的观察，不从媒体关系、解码成功、图标或几次静态截图推定。不要用全桌面截图收集无关私人窗口；必要时只采集获准的放映窗口。

用户手动验收也可以形成有效证据：记录候选SHA-256、实际目标设备／应用版本（可得时）、日期时间、页或媒体ID、单击／自动等触发方式、是否画面持续推进到预期结束、是否可听及异常。只登记用户实际报告的范围；单纯“文件打开了”不等于视频完整有声播放。收到有效结果后再更新相关状态，未做的排练和字体场景仍不冒充已完成。

## 6. 图片和视频按稳定身份映射，不能靠批次顺序

批量读取返回顺序不保证与请求顺序一致。每个素材建立稳定asset_id，至少记录：原文件SHA-256、真实文章URL、原始图注／图像身份依据、本地相对文件名、处理操作、衍生文件SHA-256、使用的slide_key及当前页码／对象。裁切或压缩后保留原图关系，不能只复用旧哈希。

使用前实际查看图像像素，并制作带可见标签的联系表，或逐张独立打开并明确标记asset_id和文件名；标签须与同一文件读取结果绑定，而不是读取后凭数组索引补标签。缩略图不清楚就单图放大。讲稿点名地点、人物、设施时，对照原文图注和画面核实；不能凭熟悉感或文件排序猜地点。

slide_key表示内容页的稳定身份，当前页码和PPT部件／对象位置用于定位。重排后更新映射并对照候选核验；同一素材出现多次要列出所有使用位置。不要在大纲和媒体清单分别手写互相矛盾的页码。

视频清单分别记录文章发布方、视频发布渠道、已核实的出品／制作方及证据定位。网页页脚的全站版权或主办文字不能用作视频出品方；片头片尾署名、官方片源说明和实际画面证据才可支持对应归属，单个台标也不自动证明全部制作主体。不明确的归属如实写待核验，不为了填满字段编造。

### 技术前提不是重复的人为审批

私有稳定工作目录确认是调用方须用证据建立的技术条件，不是要求每次送审都再向用户索要一次笼统授权。在本轮已授权工作区中，若执行者能确认是专用目录、输入/祖先目录不受不可信方控制且没有并发写入，可记录依据后传入相应确认参数。不能不检查就自动加参数，也不能把参数本身当安全保护。条件未知时，只询问缺失条件或使用另一已获准且可确认的目录；无关工作不必停止。不得为满足条件擅自修改OS权限。
